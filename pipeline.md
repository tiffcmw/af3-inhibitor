## Pipeline architecture (stages, in `code/code.ipynb`)

1. **Stage 1 — Target Justification**: rationale for why gingipains (and their autoinhibitory
   propeptides) are the target. Not executable code, just background/citations.
2. **Stage 2 — Building Phage Protein Library**: two parallel tracks that both terminate in FASTA
   candidate pools:
   - **Variant track** (2bi): extracts gingipain propeptide sequences from local UniProt FASTA
     files (hardcoded accession → propeptide-boundary map, since AF3/BLAST-verified boundaries
     aren't otherwise available), then generates all single point-substitution variants.
   - **Database track** (2bii): queries UniProt REST directly for candidate inhibitor-like
     sequences (cysteine protease inhibitor keyword `KW-0929`, mechanism-matched to gingipains)
     plus MEROPS inhibitor library files.
3. **Stage 3 — Data Filtering**: cuts the candidate pool down before the expensive AlphaFold3 step.
   - **3ai** BLOSUM62 comparative filtering for generated variants (pandas/numpy).
   - **3aii** cuDF/cupy GPU-vectorized biophysical filtering (length, hydropathy, mass) for
     database-track candidates. Falls back to CPU/pandas if `cudf`/`cupy` aren't installed.
   - **3bi** Top-N clustering by BLOSUM62 score with chemical-class diversity enforcement.
   - **3bii** MMseqs2-GPU clustering (external `mmseqs` binary, invoked via `subprocess`) with
     priority-score-based representative reselection.
   - **3c** Extracts the gingipain catalytic (peptidase) domains. Tthese become the AF3/ColabFold
     fold targets, using the same hardcoded UniProt chain-boundary map as Stage 2bi.
4. **Stage 4 — Complex Prediction**: predicts whether each surviving candidate physically binds
   the gingipain catalytic domain, ranked by ipTM/pTM.
   - **4a AlphaFold3**: generates one JSON job per candidate + a launch script that round-robins
     jobs across GPUs via `CUDA_VISIBLE_DEVICES`, calling a local `run_alphafold.py` inside Docker.
   - **4b ColabFold**: alternate/cheaper path using `colabfold_batch` directly (no separate MSA
     search step). Generates FASTA job splits, a per-GPU launch shell script
     (`output/colabfold_jobs/run_colabfold.sh`), a dependency-free Needleman-Wunsch aligner to
     verify residue numbering against the source UniProt sequence, a dependency-free PDB parser
     to check candidate-vs-active-site residue overlap, and a results parser that produces
     `master_results.tsv`. A separate results-viewer section (using `# %%` cell markers, meant for
     Jupyter or VS Code's Python interactive window) renders `master_results.tsv` plus the PNG/PDB
     files `colabfold_batch` wrote to disk.

Both Stage 2 tracks and both Stage 4 backends are independent alternatives, not a strict linear
chain. E.g. you can run the database track through ColabFold without touching AlphaFold3, or vice
versa. When editing one track/backend, check whether the parallel track needs the equivalent change.

## Data layout

- `datasets/UniProt/*.fasta` — canonical (PE=1, reviewed) RgpA/RgpB/Kgp sequences pulled from
  UniProt; source of truth for propeptide/chain boundary numbering.
- `datasets/MEROPS/` — MEROPS family C25 (clan CD, gingipain/caspase-like cysteine proteases)
  library and inhibitor download list.
- `code/output/` — all pipeline-generated intermediates (propeptides, variants, filtered/clustered
  candidates, ColabFold job splits and results, parsed score tables). Gitignored; regenerated by
  running the stages, not committed.

## Working in this notebook

- UniProt accession → propeptide/chain boundary numbers are hand-verified from each entry's
  UniProt "PTM/Processing" tab and hardcoded in CONFIG cells (Stages 2bi and 3c use the *same*
  map. Keep them in sync). Several boundaries are marked `INFERRED` rather than `CONFIRMED` in
  comments; treat those as needing verification against uniprot.org before trusting downstream
  results for that accession.
- GPU-accelerated cells (cuDF/cupy in Stage 3aii, MMseqs2 `--gpu 1` in Stage 3bii) require RAPIDS
  and a CUDA-capable GPU; the biophysical filter cell degrades to CPU/pandas automatically if
  `cudf`/`cupy` imports fail, but the clustering cell hard-requires the `mmseqs` binary on PATH.
  Note: `mmseqs --gpu 1` is only valid for `makepaddedseqdb`/`search`/`easy-search`, not `cluster`.
  An earlier version of this script got that wrong.
- AlphaFold3 and ColabFold both run on a remote GPU server, not locally from this repo: the
  notebook cells only *generate* job files/scripts (JSON configs, FASTA splits, launch shell
  scripts) locally, then print instructions for running `run_alphafold.py` / `colabfold_batch` on
  that server. `AF3_SCRIPT`/`AF3_MODEL_DIR`/`AF3_DB_DIR` in the Stage 4a CONFIG cell are
  placeholder paths that must be updated per-server.
- Environment setup (Stage 2a preamble): create a Python 3.11–3.14 venv (RAPIDS-compatible),
  install RAPIDS via the version-matched selector at docs.rapids.ai, install Docker + NVIDIA
  Docker support for AlphaFold3, and put `mmseqs`/`colabfold_batch` on PATH separately.
